## Fabric IQ란?

**Microsoft Fabric**은 데이터 엔지니어링·데이터 사이언스·실시간 분석·비즈니스 인텔리전스를 하나로 묶은 통합 분석 플랫폼입니다. **IQ**는 사용자가 **자연어**로 질문하면 구조화된 데이터에서 답을 얻을 수 있게 해 주는 Fabric의 기능으로, SQL을 몰라도 됩니다.

핵심 재료는 **온톨로지**입니다. 엔티티 타입, 속성, 관계를 형식적으로 기술한 문서죠. IQ는 온톨로지를 읽어 데이터의 모양을 이해하고, 평문 질문을 올바른 쿼리로 번역합니다.

## IQ가 온톨로지를 사용하는 방식

사용자가 *"지난달 지역별 총 매출은?"*이라고 물으면 IQ는 아래를 알아야 합니다.

1. **엔티티 타입** — `Order`, `Store`, `Region`
2. **속성** — `Order.totalAmount`, `Order.date`, `Store.region`
3. **관계** — `Order` → `placedAt` → `Store`, `Store` → `locatedIn` → `Region`
4. **식별자 속성** — 각 엔티티를 유일하게 식별하는 필드 (예: `Order.orderId`)

이 네 가지는 모두 온톨로지가 제공합니다. 온톨로지가 없으면 IQ는 "매장"과 "상품"을 구분하지 못하고, 이들을 어떻게 조인해야 할지도 모릅니다.

## 엔티티 타입

엔티티 타입은 비즈니스 객체의 범주입니다. Fabric IQ에서 각 엔티티 타입은 다음을 가집니다.

- **이름**과 선택적인 **설명**
- 하나 이상의 **속성** (타입이 지정된 컬럼)
- 인스턴스를 유일하게 식별하는 최소 하나의 **식별자 속성**

`Customer(customerId, name, email, tier)`와 같은 테이블 정의로 생각하면 됩니다.

## 속성과 타입

각 속성은 데이터 타입을 가집니다.

| 타입 | 설명 | 예시 |
|------|-------------|---------|
| `string` | 텍스트 값 | 고객 이름, 상품 SKU |
| `integer` | 정수 | 수량, 연도 |
| `decimal` | 소수 | 가격, 평점 |
| `date` | 달력 날짜 | 주문일, 생년월일 |
| `datetime` | 시간이 포함된 날짜 | 생성 타임스탬프 |
| `boolean` | 참/거짓 | 활성 여부, 프리미엄 여부 |

**식별자 속성**(키 아이콘 표시)은 결정적으로 중요합니다. IQ에게 엔티티를 어떻게 세고, 그룹화하고, 조인할지 알려 주기 때문입니다.

## 관계와 카디널리티

관계는 엔티티 타입을 연결합니다. 각 관계는 아래를 지정합니다.

- **출발지**와 **도착지** 엔티티 타입
- **이름** (동사: "places", "contains", "worksAt")
- **카디널리티** — 얼마나 많은 인스턴스가 연결될 수 있는지

| 카디널리티 | 의미 | 예시 |
|------------|---------|---------|
| One-to-one | 각 A는 정확히 하나의 B에 대응 | `Employee` → `Badge` |
| One-to-many | 각 A는 여러 B에 대응 | `Customer` → `Order` |
| Many-to-one | 여러 A가 하나의 B에 대응 | `Order` → `Store` |
| Many-to-many | 여러 A가 여러 B에 대응 | `Student` → `Course` |

IQ는 카디널리티를 사용해 정확한 집계를 생성합니다. `Customer`와 `Order` 사이의 one-to-many 관계는 "고객당 주문 수"가 유효하다는 뜻이고, 반대로 "주문당 고객 수"는 대개 1이 됩니다.

*E-Commerce 온톨로지는 IQ에 적합한 패턴을 보여줍니다. 모든 엔티티에 식별자 속성, 타입이 지정된 컬럼, 모든 관계에 카디널리티가 지정돼 있습니다.*

## IQ를 위한 설계

Fabric IQ용 온톨로지를 만들 때 다음 지침을 따르세요.

1. **엔티티 이름을 명확히** — 사용자가 실제로 말할 만한 비즈니스 용어를 사용하세요 ("Customer", "tbl_cust" ✗)
2. **설명을 붙이세요** — IQ는 설명을 활용해 비슷한 개념을 구분합니다
3. **식별자를 표시하세요** — 모든 엔티티는 반드시 하나 이상의 식별자 속성을 가져야 합니다
4. **카디널리티를 설정하세요** — IQ가 올바른 GROUP BY와 JOIN 로직을 생성하는 데 도움이 됩니다
5. **초점을 유지하세요** — 사용자가 질의할 개념만 모델링하고 모든 내부 테이블을 담지 마세요

## 핵심 정리

- Fabric IQ는 온톨로지를 사용해 자연어 질문을 SQL로 번역합니다
- 엔티티 타입, 속성, 관계, 카디널리티가 네 기둥입니다
- 정확한 카운팅과 조인을 위해 모든 엔티티에 식별자 속성이 필요합니다
- 좋은 이름과 설명은 IQ의 질의 응답 정확도를 높입니다
- IQ에 적합한 온톨로지를 시각적으로 만들 때는 [온톨로지 디자이너](#/designer)를 사용하세요

```quiz
Q: Fabric IQ의 모든 엔티티 타입에 식별자 속성이 요구되는 이유는?
- 온톨로지를 전문적으로 보이게 하려고
- IQ가 엔티티를 정확히 세고, 그룹화하고, 조인할 수 있도록 [correct]
- 엔티티의 표시 이름으로 사용하려고
- 기본 정렬 순서를 정하려고
> 식별자 속성은 엔티티 타입의 인스턴스를 유일하게 구분합니다. 이것이 없으면 IQ는 번역된 SQL에서 COUNT, GROUP BY, JOIN을 올바르게 생성할 수 없습니다.
```

```quiz
Q: 관계의 카디널리티가 Fabric IQ에 알려 주는 것은?
- 관계를 그릴 때 사용할 색상
- 관계의 각 쪽에 얼마나 많은 인스턴스가 연결될 수 있는지 [correct]
- 관계가 선택 사항인지 필수인지
- 엔티티를 표시하는 순서
> 카디널리티(one-to-one, one-to-many, many-to-one, many-to-many)는 IQ가 올바른 집계와 조인을 생성하는 데 사용됩니다. 예를 들어 한 명의 고객이 여러 주문을 갖는다는 사실을 알려 줍니다.
```
