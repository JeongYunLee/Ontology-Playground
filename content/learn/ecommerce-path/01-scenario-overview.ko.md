## 시나리오

**범용 전자상거래 마켓플레이스**의 데이터 모델을 만듭니다. 플랫폼은 다음을 다룹니다.

- 상품을 둘러보고 구매하는 **구매자**
- 재고가 추적되는 **상품**
- 결제 전 활성 세션인 **장바구니**
- 완료된 구매 거래인 **주문**
- 구매자가 상품을 평가하고 코멘트를 남기는 **리뷰**

데이터는 여러 시스템을 흐릅니다. 주문은 트랜잭션 DB, 상품 탐색은 검색 엔진, 구매자 행동은 분석 웨어하우스로 들어갑니다.

## 왜 온톨로지인가?

**"인증된 리뷰어 중, 자신이 구매하지 않은 상품에 평점을 남긴 사람은?"** 같은 질문은 구매자·리뷰·주문·상품을 조인해 여러 시스템을 넘나들며 답해야 합니다.

온톨로지가 있으면 이 질문은 그래프 패턴이 됩니다. `writes → Review → reviews → Product` 경로는 있지만 같은 상품에 대해 `places → Order → includes → Product` 경로는 없는 `Buyer` 노드를 찾으면 됩니다.

## 무엇을 만들까

| 단계 | 엔티티 | 배울 내용 |
|---|---|---|
| 1 | Buyer, Product, Order | 핵심 마켓플레이스 엔티티와 구매 흐름 |
| 2 | + Shopping-Cart | 결제 전 세션, one-to-one 관계 |
| 3 | + Review | 고객 피드백 루프로 순환 완성 |

끝날 즈음에는 둘러보기부터 리뷰까지 전체 구매자 여정을 담은 5개 엔티티, 6개 관계 온톨로지가 완성됩니다.

## 핵심 개념

- **구매 흐름** — 둘러보기부터 결제까지의 여정
- **one-to-one 관계** — 각 쪽이 정확히 하나의 파트너를 가질 때 (Buyer ↔ Cart)
- **피드백 루프** — 리뷰가 구매자를 상품으로 다시 이어 주는 방식
- **세션 엔티티** — 장바구니 같은 일시적 객체

핵심 마켓플레이스 엔티티부터 시작해 봅시다.
