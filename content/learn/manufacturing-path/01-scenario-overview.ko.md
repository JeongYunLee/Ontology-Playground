## 시나리오

**스마트 제조 시설**의 데이터 모델을 설계합니다. 공장은 다음을 관리합니다.

- 유지보수 일정과 운영 상태를 가진 공장 내 **설비**
- 온도·진동·압력 등 실시간 데이터를 수집하는 **센서**
- 우선순위와 마감이 있는 생산 작업을 추적하는 **작업 지시**
- 제조 중인 부품과 스펙·허용 오차를 나타내는 **부품**
- 검사 결과, 합격/불합격 상태, 결함 코드를 기록하는 **품질 검사**

데이터는 IoT 센서, MES(Manufacturing Execution System), ERP 플랫폼, 품질 관리 데이터베이스에서 흘러 들어옵니다.

## 왜 온톨로지인가?

**"지난주 센서 이상치가 발생한 설비 중 품질 검사에서 불합격한 부품을 만든 설비는?"** 같은 생산 질문은 IoT 텔레메트리, 생산 스케줄, 부품 추적, 검사 기록을 넘나듭니다.

온톨로지가 있으면 이렇게 매핑됩니다. `Machine → Sensor (reading > threshold)`, 그리고 `Machine → Work-Order → Part → Quality-Check (passed=false)`.

## 무엇을 만들까

| 단계 | 엔티티 | 배울 내용 |
|---|---|---|
| 1 | Machine, Sensor | IoT 관계, 텔레메트리 계층 |
| 2 | + Work-Order, Part | 생산 추적, 제조 체인 |
| 3 | + Quality-Check | 검사 루프, 생산 순환 완성 |

끝날 즈음에는 센서 모니터링부터 품질 보증까지 아우르는 5개 엔티티, 5개 관계 온톨로지가 완성됩니다.

## 핵심 개념

- **IoT 계층** — 설비가 센서를 소유하고, 판독값은 위로 흐릅니다
- **생산 체인** — 작업 지시가 부품을 생산합니다
- **품질 루프** — 검사가 생산 결정에 되먹임됩니다
- **운영 상태** — 실시간 상태 추적 (running, idle, maintenance)

공장 현장부터 시작해 봅시다.
